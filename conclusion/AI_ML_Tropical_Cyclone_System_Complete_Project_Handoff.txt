SAFETY AND SCIENTIFIC DISCLAIMER
---------------------------------------------------------------------
This project is a research and educational prototype. Predictions,
confidence scores, alerts, and track/intensity forecasts must not be
interpreted as official meteorological warnings or forecasts.
Operational tropical cyclone warnings should be obtained from
authorized meteorological agencies.

1. PURPOSE AND CURRENT STATE
=====================================================================
The system is a local end-to-end research workflow for:
  - satellite-image cyclone/non-cyclone detection;
  - CNN feature extraction and cyclone category classification;
  - sequential storm-state, wind, pressure, and track forecasting;
  - evaluation, local prediction serving, and dashboard visualization.

IMPLEMENTED:
  Steps 1-5: data collection through TCIR-IBTrACS fusion.
  Step 6: PyTorch CNN detector, manifest builder, train and inference.
  Step 7: CNN feature extraction.
  Step 8: scikit-learn MLP category classification.
  Steps 9-11: storm-aware LSTM temporal, intensity, and track models.
  Step 12: classification, regression, and Haversine evaluation.
  Step 13: local FastAPI prediction engine and threshold alerts.
  Step 14: Streamlit dashboard Pipeline Control Center.

AVAILABLE:
  data/processed/fused_dataset/tcir_ibtracs_fused.csv
  This fused dataset contains 21,076 records/rows.

REQUIRED:
  Labelled satellite image crops, trained model checkpoints, and
  generated artifacts are required for an end-to-end live prediction.

NOT CURRENTLY AVAILABLE:
  - Satellite image dataset.
  - Trained CNN checkpoint.
  - Trained MLP classifier checkpoint.
  - Trained temporal, intensity, or track checkpoints.
  - Production/cloud deployment.

The dashboard intentionally reports missing artifacts as unavailable.
No model accuracy or operational readiness is claimed.

6. STEP 6 - CNN CYCLONE IDENTIFICATION
=====================================================================
Objective: predict whether an RGB satellite crop contains a tropical
cyclone.

Input:
  data/processed/images/cyclone/
  data/processed/images/no_cyclone/

Manifest creation labels cyclone as 1 and no_cyclone as 0, validates
paths, and writes image_path,label CSV records. The CNN uses PyTorch
convolution, batch normalization, ReLU, max-pooling, adaptive average
pooling, dropout, and a final binary logit. Images are loaded through
Pillow, converted to RGB, resized to 256x256 by default, and normalized.

Training uses a stratified train/validation split, BCEWithLogitsLoss,
AdamW, and reports validation accuracy, precision, recall, F1, and
ROC-AUC when both classes exist. Inference outputs preserved manifest
metadata plus cyclone_probability and cyclone_detected. Default
threshold is 0.5.

Commands:
  python -c "from cyclone_identification.dataset import build_manifest; build_manifest('data/processed/images/cyclone', 'data/processed/images/no_cyclone', 'data/processed/detections/train_manifest.csv')"
  python -m cyclone_identification.training.train --manifest data/processed/detections/train_manifest.csv
  python -m cyclone_identification.inference --manifest data/processed/detections/train_manifest.csv --checkpoint models/cyclone_cnn.pt

Important files:
  src/cyclone_identification/dataset.py
  src/cyclone_identification/model.py
  src/cyclone_identification/transforms.py
  src/cyclone_identification/training/train.py
  src/cyclone_identification/inference.py

Status: code implemented. Training is blocked until labelled images exist.
Next step: positive detection records enter Step 7.

8. STEP 8 - CYCLONE CATEGORY CLASSIFICATION
=====================================================================
Objective: assign a cyclone category from CNN feature vectors.
Input: image_features.npy and feature_metadata.csv.
Technology: scikit-learn MLPClassifier, hidden layers (128,64), early

A category label column is preferred. The code has a USA_WIND fallback,
but category definitions must be reviewed against the project's selected

9. STEP 9 - TEMPORAL STORM MODEL
=====================================================================
Objective: model next storm state from historical ordered observations.
Input:
  data/processed/fused_dataset/tcir_ibtracs_fused.csv
Default features/targets:
  LAT_IBTRACS, LON_IBTRACS, USA_WIND, USA_PRES
Model: PyTorch LSTM followed by dropout and a linear output head.
Processing: rows sort by SID and TIME; default lookback is four historic
states; each window predicts the next state. Training-partition mean/std
are used for feature/target scaling and inverse scaling.
Validation: implemented split is by SID, so a storm is not split across
train and test partitions.
Output:
  models/temporal_state_lstm.pt
  models/temporal_state_lstm.predictions.csv
Command:
  python -m temporal_model.pipeline --data data/processed/fused_dataset/tcir_ibtracs_fused.csv

12. STEP 12 - MODEL EVALUATION
=====================================================================
Classification metrics: accuracy, weighted precision, weighted recall,
and weighted F1.
Regression metrics: MAE and RMSE.
Track metrics: mean and median Haversine geographic error in kilometres.

Haversine concept:
  a = sin^2((lat2-lat1)/2) + cos(lat1)*cos(lat2)*sin^2((lon2-lon1)/2)
  d = 2 * R * asin(sqrt(a))
Coordinates are converted to radians and R is Earth radius.

Command:
  python -m model_evaluation.pipeline --data <predictions.csv> --task track --actual actual_LAT_IBTRACS,actual_LON_IBTRACS --predicted predicted_LAT_IBTRACS,predicted_LON_IBTRACS

Output defaults to data/processed/evaluation/metrics.json. Haversine
measures point distance, not every quality property of a full trajectory.

16. DATA LEAKAGE, VALIDATION, AND RECOMMENDATIONS
=====================================================================
IMPLEMENTED:
  - LSTM sequence splitting is storm-aware: SID partitions storms before
    train/test sequence use.
  - Forecast scaling statistics use training sequences.
  - Step 6 uses a stratified image train/validation split.

WHY:
  Random row splitting can put records from one storm into both train and
  test data and inflate apparent performance. Future observations must
  never be used as history for an earlier forecast.

RECOMMENDED IMPROVEMENTS:
  - Hold out complete unseen storms for final evaluation.
  - Persist split identifiers, random seeds, dataset version, parameters,
    normalization values, and model versions.
  - Maintain strict temporal ordering.
  - Ensure no duplicate/near-duplicate image frames cross image splits.
  - Audit cyclone/non-cyclone/category imbalance.
  - Audit missing values, duplicates, units, and storm associations.
  - Perform hyperparameter tuning and uncertainty estimation only with
    leakage-safe validation.

18. TROUBLESHOOTING
=====================================================================
ModuleNotFoundError/PYTHONPATH:
  Set $env:PYTHONPATH = 'src' from tropical-cyclone-ai.
  Verify: python -c "import cyclone_identification"

Missing dataset/images:
  Verify the fused CSV path or add valid labelled image files to the two
  expected image folders, then rebuild the manifest.

Missing checkpoint/dashboard unavailable:
  Train the relevant stage and keep its output in models/ or the expected
  processed folder. Verify /health and Pipeline Control Center status.

CSV column mismatch:
  Confirm SID, TIME, LAT_IBTRACS, LON_IBTRACS, USA_WIND, and USA_PRES
  are present for default LSTM commands.

Incorrect category column:
  Inspect feature_metadata.csv; provide a complete, project-approved
  label column before training.

Tensor shape error:
  Provide exactly checkpoint lookback rows with expected feature order.

FastAPI/dashboard fails to start:
  Install dependencies, set PYTHONPATH for the API, and ensure ports
  8000 and 8501 are not already used. Verify API /health before testing
  dashboard API communication.
